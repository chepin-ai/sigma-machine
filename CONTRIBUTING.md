# Contributing to Sigma Machine

Thank you for your interest in contributing to the Sigma Machine project!

## How to Contribute

### Reporting Issues
- Use GitHub Issues to report bugs or request features
- Include a minimal reproducible example for bugs
- Tag issues with appropriate labels: `bug`, `feature`, `theory`, `experiment`

### Submitting Code
1. Fork the repository
2. Create a feature branch (`git checkout -b feature/amazing-feature`)
3. Commit your changes (`git commit -m 'Add amazing feature'`)
4. Push to the branch (`git push origin feature/amazing-feature`)
5. Open a Pull Request

### Code Standards
- Follow PEP 8 for Python code
- Include docstrings for all public functions
- Add tests for new features
- Maintain backward compatibility when possible

### Theoretical Contributions
We welcome theoretical contributions in the form of:
- Mathematical proofs (submitted as LaTeX documents in `docs/theory/`)
- Computational experiments (Jupyter notebooks in `examples/`)
- Literature reviews (Markdown documents in `docs/reviews/`)

### Experimental Collaborations
If you are running physical experiments related to the Sigma Machine:
- Share data in standardized formats (HDF5, JSON)
- Include calibration procedures and error analysis
- Document the physical platform used

## Review Process
All contributions will be reviewed by the core team. For theoretical
contributions, we may seek external peer review from experts in the
relevant fields (number theory, quantum physics, category theory).

## Code of Conduct
This project adheres to a strict code of conduct. Be respectful,
constructive, and inclusive in all interactions.
